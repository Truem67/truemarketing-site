Getting Started
Base URL & Authentication

All requests go to the base URL below. Authenticated endpoints require an x-api-key header. Keys are prefixed dsx_ followed by 64 hex characters — treat them like passwords. Contact johan@doxseal.co.za to request a key.

Base URL https://tm-server-myv6.onrender.com

Pass your key in the request header on every authenticated call:

Header
x-api-key: dsx_4a2f8b1c9e3d7a5f0b8c2e4d6f1a3b5c7e9f2a4b6c8d0e2f4a6b8c0d2e4f6a8b

Keys are shown once on creation and cannot be retrieved again. Store yours immediately in an environment variable — never hardcode it in source.

POST /api/v1/seal x-api-key required

Seals a message or file fingerprint permanently on the BSV blockchain via an OP_RETURN transaction. Provide either message (plain text — the server computes the SHA-256) or fileHash (a SHA-256 you computed client-side). Documents never leave your system when using fileHash.

Request body
FieldTypeDescription
subject required string Document title or description. Max 200 chars.
message optional* string Plain-text content to seal. Server hashes it. Max 10,000 chars. Use instead of fileHash.
fileHash optional* string Pre-computed SHA-256 hex (64 chars) of a file hashed on your side. The file itself is never transmitted.
fileName optional string Original filename for reference in the response. Not stored on-chain.
recipient optional string Recipient email address. Embedded in the on-chain OP_RETURN record.

* Either message or fileHash is required — not both.

curl — seal a message
curl -X POST https://tm-server-myv6.onrender.com/api/v1/seal \
  -H "x-api-key: dsx_your_key_here" \
  -H "Content-Type: application/json" \
  -d '{
    "subject":   "Employment Contract — Sarah Johnson",
    "message":   "I, Sarah Johnson, accept the terms of employment as Senior Analyst, effective 1 June 2026.",
    "recipient": "sarah.johnson@company.co.za"
  }'
curl — seal a file by hash
curl -X POST https://tm-server-myv6.onrender.com/api/v1/seal \

Node.js
// Node 18+ built-in fetch. Store your key in an env var.
const API_KEY = process.env.DOXSEAL_API_KEY;
const BASE    = 'https://tm-server-myv6.onrender.com';

async function sealDocument(subject, message, recipient) {
  const res = await fetch(`${BASE}/api/v1/seal`, {
    method:  'POST',
    headers: {
      'Content-Type': 'application/json',
      'x-api-key':    API_KEY
    },
    body: JSON.stringify({ subject, message, recipient })
  });
  if (!res.ok) throw new Error((await res.json()).error);
  return res.json();
}

const result = await sealDocument(
  'Written Warning — J. Smith',
  'First written warning for repeated lateness. Date: 1 June 2026.',
  'john.smith@company.co.za'
);
console.log(result.txid);           // BSV transaction ID
console.log(result.certificateUrl); // shareable proof link

    'subject':  'Signed Contract — Acme',
    'fileHash': file_hash,
    'fileName': 'contract.pdf'
})
print(r.json()['certificateUrl'])
PHP
$apiKey = getenv('DOXSEAL_API_KEY');
$base   = 'https://tm-server-myv6.onrender.com';

function doxseal_seal(string $subject, string $message, string $recipient = ''): array {
    global $apiKey, $base;
    $ch = curl_init("$base/api/v1/seal");
    curl_setopt_array($ch, [
        CURLOPT_RETURNTRANSFER => true,
        CURLOPT_POST           => true,
        CURLOPT_HTTPHEADER     => ["x-api-key: $apiKey", 'Content-Type: application/json'],
        CURLOPT_POSTFIELDS     => json_encode(array_filter([
            'subject'   => $subject,
            'message'   => $message,
            'recipient' => $recipient
        ]))
    ]);
    return json_decode(curl_exec($ch), true);
}

$seal = doxseal_seal('Invoice #INV-2026-042', 'Amount: R15,000. Due: 30 June 2026.', 'client@firm.co.za');
echo $seal['certificateUrl'];

Technical Background
How Sealing Works

When you call POST /api/v1/seal, DoxSeal computes (or accepts) a SHA-256 fingerprint of your content and records it in an OP_RETURN output on the BSV blockchain. This creates a permanent, immutable timestamp — no third party can alter or delete it.

The record is publicly verifiable by anyone on WhatsOnChain using the transaction ID — no DoxSeal account required.

Document privacy: When you use fileHash, the document never leaves your system. Only the 64-character fingerprint is transmitted. The original document cannot be reconstructed from a SHA-256 hash.

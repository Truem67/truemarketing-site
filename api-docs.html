Developer Documentation

DoxSeal REST API

Seal documents programmatically from any system — CRM, DMS, ERP, or custom workflow. Every seal creates a permanent, independently verifiable blockchain record.

Access available on request. API keys are issued manually to qualified integrators and enterprise clients. Contact johan@doxseal.co.za to request access.

Getting Started
Authentication

All /api/v1/seal requests require an API key passed in the x-api-key header. API keys begin with dsx_ followed by 64 hex characters. Keys are generated once and never stored in plain text — save yours immediately on receipt.

Example header
x-api-key: dsx_4a2f8b1c9e3d7a5f0b8c2e4d6f1a3b5c7e9f2a4b6c8d0e2f4a6b8c0d2e4f6a8b
Base URL
https://tm-server-myv6.onrender.com

Rate limit: 60 requests per minute per API key. Exceeding this returns HTTP 429.

POST /api/v1/seal Requires x-api-key

Seals a message or file fingerprint permanently on the BSV blockchain. Either message (the server computes the SHA-256) or fileHash (pre-computed SHA-256 you computed client-side) must be provided — not both. Documents never leave your system.

🔑 x-api-key required
Request body
FieldTypeDescription
subject required string Short description of what is being sealed. Max 200 chars.
message optional string Plain-text content to seal. Server computes SHA-256. Max 10,000 chars. Use instead of fileHash.
fileHash optional string Pre-computed SHA-256 hex (64 chars) of a file. Computed on your side — file never uploaded.
fileName optional string Original filename — stored in response metadata only, not on-chain.
recipient optional string Email address of the document recipient. Embedded in the on-chain record.
Example — seal a message
curl -X POST https://tm-server-myv6.onrender.com/api/v1/seal \
  -H "x-api-key: dsx_your_key_here" \
  -H "Content-Type: application/json" \
  -d '{
    "subject":   "Employment Contract — Sarah Johnson",
    "message":   "I, Sarah Johnson, accept the terms of employment as Senior Analyst, effective 1 June 2026, at R480,000 per annum.",
    "recipient": "sarah.johnson@company.co.za"
  }'
Example — seal a file by its hash
curl -X POST https://tm-server-myv6.onrender.com/api/v1/seal \
  -H "x-api-key: dsx_your_key_here" \
  -H "Content-Type: application/json" \
  -d '{
    "subject":  "Signed NDA — Acme Corp",
    "fileHash": "a3f2c1b8e7d6c5b4a3f2c1b8e7d6c5b4a3f2c1b8e7d6c5b4a3f2c1b8e7d6c5b4",
    "fileName": "acme-nda-signed-2026.pdf"
  }'

POST /api/v1/verify No auth required

Integration Examples
Code Samples
Node.js
// npm install node-fetch  (or use built-in fetch in Node 18+)
const API_KEY = process.env.DOXSEAL_API_KEY;
const BASE    = 'https://tm-server-myv6.onrender.com';

async function sealDocument(subject, message, recipient) {
  const res = await fetch(`${BASE}/api/v1/seal`, {
    method:  'POST',
    headers: {
      'Content-Type': 'application/json',
      'x-api-key':    API_KEY
    },
    body: JSON.stringify({ subject, message, recipient })
  });
  if (!res.ok) throw new Error((await res.json()).error);
  return res.json();
}

// Usage
const result = await sealDocument(
  'Written Warning — J. Smith',
  'First written warning issued for repeated lateness. Date: 1 June 2026.',
  'john.smith@company.co.za'
);
console.log(result.certificateUrl);
// → https://doxseal.co.za/verify.html?txid=...
Python
import requests, os

API_KEY = os.environ['DOXSEAL_API_KEY']
BASE    = 'https://tm-server-myv6.onrender.com'

def seal_document(subject, message, recipient=None):
    headers = {'x-api-key': API_KEY, 'Content-Type': 'application/json'}
    payload = {'subject': subject, 'message': message}
    if recipient:
        payload['recipient'] = recipient
    r = requests.post(f'{BASE}/api/v1/seal', json=payload, headers=headers)
    r.raise_for_status()
    return r.json()

def seal_file(subject, file_path, recipient=None):
    import hashlib
    sha256 = hashlib.sha256()
    with open(file_path, 'rb') as f:
        for chunk in iter(lambda: f.read(65536), b''):
            sha256.update(chunk)
    return seal_document.__wrapped__(subject, sha256.hexdigest(), file_path, recipient)

# Seal a file without uploading it
headers = {'x-api-key': API_KEY, 'Content-Type': 'application/json'}
import hashlib
h = hashlib.sha256(open('contract.pdf', 'rb').read()).hexdigest()
r = requests.post(f'{BASE}/api/v1/seal', headers=headers, json={
    'subject':  'Signed Contract — Acme',
    'fileHash': h,
    'fileName': 'contract.pdf'
})
print(r.json()['certificateUrl'])
PHP
$apiKey = getenv('DOXSEAL_API_KEY');
$base   = 'https://tm-server-myv6.onrender.com';

function doxseal_seal(string $subject, string $message, string $recipient = ''): array {
    global $apiKey, $base;
    $ch = curl_init("$base/api/v1/seal");
    curl_setopt_array($ch, [
        CURLOPT_RETURNTRANSFER => true,
        CURLOPT_POST           => true,
        CURLOPT_HTTPHEADER     => ["x-api-key: $apiKey", 'Content-Type: application/json'],
        CURLOPT_POSTFIELDS     => json_encode(array_filter([
            'subject'   => $subject,
            'message'   => $message,
            'recipient' => $recipient
        ]))
    ]);
    $result = json_decode(curl_exec($ch), true);
    curl_close($ch);
    return $result;
}

$seal = doxseal_seal('Invoice #INV-2026-0042', 'Amount: R15,000. Due: 30 June 2026.', 'client@firm.co.za');
echo $seal['certificateUrl'];
Technical Background
How DoxSeal Sealing Works

When you call POST /api/v1/seal, DoxSeal computes (or accepts) a SHA-256 fingerprint of your content and records it in an OP_RETURN output on the BSV blockchain. This creates a permanent, tamper-proof timestamp.

The record is public and independently verifiable by anyone — without any account or access to DoxSeal. Direct verification via WhatsOnChain: whatsonchain.com/tx/{txid}

Document privacy: When using fileHash, the document never leaves your system. Only the 64-character fingerprint is transmitted and recorded on-chain. Even if the blockchain record were public, the original document cannot be reconstructed from a SHA-256 hash.
